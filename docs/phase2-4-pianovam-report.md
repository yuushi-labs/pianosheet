## 1. 評価方法（アプリと同一条件の担保）

`onnxruntime-android` はデスクトップ JVM で動かないため、**モデル部分だけ**を Python（同じ `nmp.onnx`・同じ 2.0 秒窓 / 1.0 秒ホップ・`BasicPitchDecoder` の移植）で実行し、**推論より後はアプリの Kotlin そのもの**を `PianoVamBenchmarkTest` で走らせた。

```
WAV → リサンプル 22.05k → Denoiser → StartupGuard → 2.0 s 窓 / 1.0 s ホップ
    → Basic Pitch ONNX → decode（Python・Kotlin と同一移植）
    → NoteCandidateFilter → StartupGuard.isStartupArtifact → FinalNoteMerger.mergeDetailed
    → HarmonicRealnessFilter → ScoreBuilder        ← ここから先はすべて Kotlin
```

- 移植の一致確認（変更前のコードで実施）: Hanon は**音符集合まで完全一致**（356 音、F1 0.795）、Yiruma は 210 音 vs 209 音（倍音チェックの境界 1 音のみ差）。したがって変更前の数値は Python 側で取り、変更後は Kotlin 側で取っている。
- 変更後はフィクスチャ 4 本（T-010/T-014/T-019/T-020）も Kotlin で走らせ、Python 側の数値と一致することを確認した（§3.7）。
- 再現: `PIANOSHEET_PIANOVAM_DIR=<dir> ./gradlew :app:testDebugUnitTest --tests '*PianoVamBenchmarkTest*'`（環境変数が無い CI では自動スキップ）。

### 「正解」の作り方と限界

PianoVAM の MIDI は**テンポ 120 固定・4/4・C major のダミーメタ**しか持たない（Disklavier の生キャプチャ）。そのため音符・発音時刻・長さは MIDI/TSV を正解とし、テンポ・拍子・調は次の**独立な基準**と比較した。譜面の調号そのものではない。

- テンポ: 音声そのものへの librosa ビート追跡（`beat_track`, start_bpm=100）。2 倍/半分は「オクターブ許容」で判定。
- 調: 正解 MIDI の音符に music21（Krumhansl）をかけた結果。主音＋旋法で比較。
- 拍子: 正解音符のアクセント周期（4/4・3/4・2/4・6/8 のうち下拍の立ち方が最も強いもの）。
- 小節: MIDI に小節情報が無いため、「小節頭に置いた拍の正解アクセント量 ÷ 他の拍の平均」を整合性の指標にした（1.0 = アクセントなし）。

## 3. 何を変えたか（すべて PianoVAM で前後比較）

### 3.1 復号パラメータ（`BasicPitchConstants`, `BasicPitchDetector`）

1 要素ずつ動かした実測（6 曲 micro F1、変更前 0.6975）:

| パラメータ | 値 | micro F1 | 判断 |
|---|---|---|---|
| onset 閾値 | 0.50 / 0.45 / 0.40 / 0.35 | 0.698 / 0.684 / 0.658 / 0.620 | 下げると悪化。**最終解析は 0.55** を採用 |
| frame 閾値 | 0.30 / 0.25 / 0.20 | 0.698 / 0.716 / 0.717 | 下げると再現率 +0.06 だが精度が落ちる。**0.30 のまま**（§6 に犠牲の定量） |
| 最小音符長 | 11 / 8 / 6 / 4 フレーム | 0.698 / 0.730 / 0.741 / 0.741 | **6 フレーム（70 ms）** を採用。128 ms は 32 分音符を切り捨てていた |
| melodia パス | on / off | 0.750 / 0.768 | 単独では off が良いが和音一致は on が上（0.53 vs 0.51）。**on のまま**、onset 床を 0.20 → 0.30 |
| 統合の許容幅 | 60 / 80 / 100 ms | 0.781 / 0.781 / 0.780 | 差なし。**80 ms のまま** |

ライブ（2.0 s 窓 / 0.25 s ステップ）では最小音符長だけが効いた: **0.710 → 0.760**（p95 遅延は 491–514 ms で不変、ステップ計算 23 ms も不変）。ライブの onset 閾値は 0.50 のまま。

### 3.2 倍音実在チェックに「持ち主」条件（`HarmonicRealnessFilter`）

v1.4 の「2f0 が 10% 未満かつ 3f0 が 5% 未満なら純音 1 本＝ゴースト」は、**2〜3 オクターブ下に同じ時刻で打鍵された音があるときだけ**適用するようにした（`requireOwnerNote`、24/36 半音、±80 ms）。

| 条件（melodia off の組合わせ上で） | micro F1 |
|---|---|
| 純音ルールのみ（v1.4） | 0.7805 |
| 純音＋持ち主条件 | **0.8035** |
| フィルタ無し | 0.8048 |

= 純音ルールは実在の高音（和音の上声など）を消していた。持ち主条件を付けるとクリーンな録音ではほぼ何も消さず（0.8035 ≒ 無し）、ユーザーの実録音（3.2 kHz のホイッスル入り）では従来どおり 8 倍音ゴーストを除去する（`RealTakeAnalysisTest`: 高音 102 音を検査、2 音のみ削除 → ゴースト 0）。

### 3.3 短い音は「打鍵の強さ」を要求（`FinalNoteMerger`、T-014 の悪化の修正）

最小音符長を 6 フレームに下げると、ノイズ入り音源で 80–120 ms の短いノイズ塊が音符として通ってしまった。**120 ms 未満の音は onset 強度 0.45 以上を要求**する条件を統合後の抑制（`suppressGhosts`）に加えた。

切り分け（フィクスチャの F1、変更前 / 各変更を単独で適用）:

| 構成 | T-014 | T-019 | T-020 | T-010 | macro（19本） |
|---|---|---|---|---|---|
| 変更前 | 0.923 | 0.500 | 0.774 | 0.889 | 0.9163 |
| 最小音符長 6 のみ | **0.800** | 0.429 | 0.686 | 1.000 | 0.9092 |
| onset 0.55 のみ | 0.960 | 0.500 | 0.800 | 0.889 | 0.9318 |
| onset 床 0.30 のみ | 0.923 | 0.600 | 0.857 | 0.889 | 0.9331 |
| 3つ全部（短い音の条件なし） | 0.857 | 0.545 | 0.857 | 1.000 | 0.9451 |
| **3つ全部＋短い音の条件（採用）** | **0.923** | **0.545** | **0.889** | **0.974** | **0.9489** |

原因は最小音符長だけで、短い音の条件を足すと T-014 は変更前と同じ 0.923 に戻り、T-020 は 0.774 → 0.889、T-010 は 0.889 → 0.974 と改善した。PianoVAM 6 曲では削除 0 音（影響なし）。Kotlin で直接走らせた値（`PianoVamBenchmarkTest`）も T-014 0.923 / T-019 0.545 / T-020 0.889 / T-010 0.974 で一致する。

### 3.4 ノイズ除去の強さと入力音量（`DenoiseStrength`, `InputMonitor`）

PianoVAM 4 曲で **clean / −34 dBFS / SNR 20 dB / SNR 12 dB** × 4 強度を実測（平均 F1）:

| | off | weak | standard | strong |
|---|---|---|---|---|
| clean | 0.797 | 0.824 | **0.830** | — |
| quiet (−34 dBFS) | 0.829 | **0.845** | 0.835 | — |
| SNR 20 dB | 0.808 | 0.819 | **0.826** | — |
| SNR 12 dB | 0.783 | **0.789** | 0.779 | — |
| **平均** | 0.803 | **0.819** | 0.817 | 0.78–0.85（全条件で最下位） |

weak と standard の差は誤差の範囲（0.819 vs 0.817）で、正解付きフィクスチャでは standard が上（0.9489 vs 0.9252）。**既定は standard のまま変更しない**。strong は全条件で悪化するので選ばない。

- **音量正規化は入れない**（実測で無効果）: −34 dBFS に落とした音源と元音源の F1 差は < 0.001 で、モデルの log-mel 前段はレベル不変。
- 代わりに `InputMonitor` で **RMS/ピーク（dBFS）・クリップ率・無音継続時間**を監視し、録音画面に「音が割れています／入力が小さいです／音が届いていません」を出す（録音そのものは無加工のまま）。

### 3.5 拍子・小節線（`TimeSignatureEstimator`, `ScoreBuilder`）

1. **下拍の位相を推定**: 従来は「最初の音＝小節頭」と決め打ちしていたので、アウフタクトで始まる演奏ではすべてのアクセントが小節の内側に落ち、拍子推定そのものが崩れていた。各拍子候補を**その候補の最良の位相**で採点し、勝った位相を返す。
2. **低音を重く見る**: 和音の上声を全部数えるとバスの音より和音が重くなり小節頭が 2 拍目に移る（Gymnopédie が 2/4 になった）。同一打鍵の中では最下音を 1.0、それ以外を 0.3 で数える。
3. **書きやすい拍子を優先**: 4/4 = 1.0、3/4 = 0.98、6/8 = 0.96、2/4 = 0.94。2/4 は行進曲の記号なので、明確に勝たない限り 4/4 にする。
4. **アウフタクトを小節として書く**: 位相 p が 0 でなければ、0〜p を短い第 1 小節とし、MusicXML では `implicit="yes"` を付ける。

実測: 拍子の一致 **3/6 → 4/6**、小節頭のアクセント比 **1.12 → 1.42**（Scarlatti 1.24→1.79、Schubert 0.97→1.61、Improvisation 1.33→1.99、Last Carnival 1.01→0.92 と 1 曲だけ悪化）。

### 3.6 調号（`KeyEstimator.simplifyEnharmonic`）

7♯（嬰ハ長調）は 5♭（変ニ長調）と同じ調で、7♯ の調号は臨時記号にダブルシャープ（G に対して F𝄪）を強いる。**臨時記号が実際に減るときだけ**異名同音へ移す（7→−5、−7→+5。6 は変化なし）。

- ユーザーの実録音: C# major（7♯）→ **D♭ major（5♭）**。
- PianoVAM Yiruma: 7♯ → −5（同じ調）。
- 主音・旋法での一致は 3/6 のまま（Scarlatti と Improvisation は転写の誤りが原因。正解音符で同じ推定器を通すと 4/6）。

### 3.7 臨時記号・小節内の重複

`ScoreBuilder` は小節ごとに `accidentalsInEffect` をリセットし、同じオクターブ・同じ音名の臨時記号は小節内で 1 回だけ印刷する（既存動作を維持、テストあり）。

## 6. Improvisation（#70）が 0.667 に留まる理由

FN 190 音 / FP 83 音の内訳を診断した。

### 6-1. 取りこぼし（FN）

| 診断 | 結果 |
|---|---|
| 同じ時刻（±40 ms）に**別の音が検出されている** | **163 / 190（86%）** = 和音の一部だけが欠けている |
| 欠けた音の**モデル自身の活性**（note 出力の最大値） | 0.1 未満 2% / **0.1–0.3 が 75%** / 0.3 以上 23% |
| 音域 | C4 未満 54 / C4–C6 92 / C6 以上 44 |
| 直前の音との間隔 | 90 ms 未満は 0%（速さの問題ではない） |

つまり **モデルが「ある」と 3 割前後しか思っていない音**で、フレーム閾値 0.30 の下にいる。鍵盤を叩いた音としては弱く、ペダルで濁った低音の上の和音内声がこの帯に落ちる。

### 6-2. 誤検出（FP）

| 診断 | 結果 |
|---|---|
| 同時に鳴る音の 2〜3 オクターブ上（倍音ゴースト） | 30 / 83 |
| 同じ音高が 150 ms 以内に再度出た（重複） | 8 / 83 |
| 音域 | C3 未満 41 / C3–C4 33 / C4–C5 7 / C5 以上 2 |
| 正解との音程（同一時刻の最寄り） | +7 半音 15・−12 半音 14・+12 半音 7・−5 半音 4 |

FP の大半は低音域の部分音（5 度上・オクターブ下）で、**他の音の倍音として説明できてしまう**もの。ここを削る規則は、実在の低音や左手のオクターブも一緒に削る（§7 で実測）。

### 6-3. 「もっと上げる」と何が犠牲になるか

| 手段 | #70 | 全体 micro F1 | 代償 |
|---|---|---|---|
| 現状（frame 0.30） | 0.667 | **0.793** | — |
| frame 0.25 | **0.686** | 0.803 | T-014 0.923 → 0.774、T-019 0.545 → 0.375、精度 0.861 → 0.856 |
| frame 0.20 | 0.644 | 0.770 | 精度 0.771（−0.09）。ノイズ入りで誤検出が急増 |
| 低域の onset 床を上げる（C3 未満 0.7） | 0.659 | 0.783 | 再現率 −0.015（実在の低音を落とす） |
| オクターブ下ゴースト除去 | 0.667 | 0.792 | 効果なし（FP の 17% は消えるが TP も同数消える） |
| 倍音実在チェックの音域を C4 まで拡大 | 0.667 | 0.792 | 効果なし（低域の FP は 2・3 倍音を持っている） |
| スペクトルピークによる和音補完 | **0.703** | 0.744 | 精度 0.717（−0.14）。補完した音の 6 割が誤り |
| 2 回目の低閾値復号＋強い打鍵での限定採用 | 0.669 | 0.793 | ほぼ効果なし（+0.002） |

**結論**: Improvisation の 0.667 は、230 KB の汎用モデル（Basic Pitch）が「ペダルで濁った低音の上の密集和音」で内声を分離できないことによる上限で、後処理では取り返せない。上げる道は 2 つだけで、どちらも代償が大きい。

1. **閾値を下げる**（frame 0.25）: #70 は +0.019 だが、ノイズ入り音源の精度が落ち、T-014 が 0.15 悪化する。
2. **別モデル**（ピアノ専用の `piano_transcription_inference` 等）: Phase 2.2 の実測では同じ実録音で F1 0.98 相当（251 音）だが、モデル 165 MB・ピーク RAM 990 MB・実時間比 0.78（2 コア）で、端末内の 2 秒ライブ経路には載らない。録音後の最終解析をサーバー（自宅 Raspberry Pi 4 で 3 分の録音に 10〜25 分）で行う構成が現実的で、これは Phase 2.2 レポートの「案B」のまま。

## 7. 変えなかったこと（測って採らなかった）

- **音量正規化**: 上記のとおり無効果（`InputMonitor` の警告のみ採用）。
- **強ノイズ除去（strong）**: 全条件で悪化。
- **melodia パスの無効化**: PianoVAM では F1 +0.014 だが和音一致が −0.01、合成では −0.03。和音の完全性を優先して残した。
- **frame 閾値 0.25**: #70 と Schubert は上がるが、T-014/T-019 が悪化（§6-3）。
- **和音の相方（chord mate）復活**: 強い打鍵の近傍にある弱い候補を残す規則 → 再現率 +0.002、精度 −0.014。
- **2 回目の低閾値復号**: 強い打鍵に限定して採用 → +0.0015。
- **スペクトルピークによる和音補完**: 再現率 +0.036、精度 −0.144（F1 −0.05）。
- **オクターブ下ゴースト除去・低域の床・倍音チェックの低域拡大**: いずれも効果なし〜悪化。
- **低音重み付けによる調推定**: 変化なし（正解音符でも 4/6 のまま）。
- **ウィンドウ重なりの増加（0.5 s ホップ）**: 計算量 2 倍に対して、既存の統合で重複がほぼ取れているため**未テスト**。

## 8. 未解決・既知の制限

- **音の長さ**: ペダル無しの音でも中央値 +23 ms（Hanon）〜+145 ms（Improvisation）長い。正解の `key_offset` は「指が離れた時刻」で、実際の音はその後に減衰するため、この差の全部が誤りではない。ペダル込みの `frame_offset` と比べると −2.1〜+0.02 s と大きく振れる（ペダルは推定していない）。楽譜の音価は 16 分グリッドへ量子化するので表記への影響は限定的。
- **密な曲の取りこぼし**: Schubert（R 0.599）と Improvisation（R 0.590）は §6 のとおりモデル上限に近い。
- **拍子**: 3/4 と 2/4、2/4 と 4/4 の区別はアクセントだけでは決めきれない（Scarlatti 3/4 → 4/4、Schubert 2/4 → 4/4）。ユーザーが拍子を上書きできる UI（仕様 §5.6）が最終的な逃げ道。
- **テンポ**: Improvisation は 95.5 BPM（基準 110、−13%）。正解音符で同じ推定器を通すと 107 になるので、原因は転写の誤り。
- **テンポ・拍子・調の基準は譜面ではない**（PianoVAM の MIDI にメタ情報が無いため）。数値は「独立な推定どうしの一致」として読むこと。
- OSMD での実描画は、今回の MusicXML について music21 の再読込と小節演算テストまで確認し、ブラウザでの目視は行っていない（前版のビューワーは変更していない）。
