# 楽譜の先頭: 録音開始の無音と弱起の扱い（0.4.3）

対象: `0.4.3-phase2`（versionCode 10）
要望（ゆうし）:

> あと、録音開始してから最初の音がなるまでの間も楽譜に出てるから、最初の音が鳴ってから次の数音から推測してちゃんと最初に空白がないようにして
> 裏拍から開始とかにも対応させてね

## 症状

1. 録音ボタンを押してから弾き始めるまでの待ち時間が、楽譜の**先頭の空白（休符・空の小節）**として出る。
2. 裏拍・弱起（アウフタクト）で始まる演奏が、拍頭に押し込まれたり、先頭に余計な休符が出たりする。

## 原因

先頭の音は「その録音の最初の音符」がそのまま **beat 0** になる（`ScoreBuilder` の `originSec = cleaned.minOf { it.onsetSec }`）。
そのため、演奏前の音が 1 つでも音符として残ると、そこが原点になり、本当の演奏開始までの区間が休符・空の小節として刷られる。
実際に 3 つの経路があった。

| # | 経路 | 中身 |
|---|---|---|
| ① | 解析モデルが**無音を音符として報告**する | テスト用のジムノペディ実録音では、録音開始 23 ms に低音 2 音（0.6 / 0.34 の確度、長さ 1.9 s / 0.8 s）が乗っていた。実際にピアノが鳴るのは 0.78 s から。これが原点になると先頭に 1 拍分の空白と余計な小節が入る |
| ② | **タップ音・環境音**（演奏前の物音） | 録音開始直後のタップが音符として残ると、そこが原点になるだけでなく、**拍グリッドが半拍ズレる**のでテンポ・拍子の推定まで壊れる（4/4 → 2/4、先頭に 11 小節分の休符、という再現をテストで固定） |
| ③ | ライブ楽譜（録音中の `StaffCanvas`） | 音符の x 座標が `onset × px/秒`、つまり**録音開始が原点**だった。弾き始めるまで待つと、その待ち時間が五線の左端に空白として描かれる |

弱起・裏拍そのものの処理（`TimeSignatureEstimator` の `phaseBeats` → 先頭の弱起小節 + `implicit="yes"`）は既にあったが、
①②で原点がずれると弱起の長さも拍も全部ずれるため、体感としては「裏拍に対応していない」状態だった。

## 修正

### 1. 無音の先頭を落とす（`core/dsp/SilenceHead`）

20 ms フレームの RMS で「録音が実際に鳴り始めた時刻」を測る。

- しきい値は**その録音自身**に合わせる（最も大きいフレームの 1 %、ただし -55 dBFS を下限）。小さい演奏を無音と誤判定せず、騒がしい部屋ではしきい値が上がる。
- しきい値を超えたフレームのあと **100 ms 続けて鳴っている**ことも条件にするので、単発のクリックは開始点にならない。
- `FinalTranscriber` が**無加工の録音**（ノイズ除去前）で測り、`ScoreBuildOptions.soundStartSec` として渡す。

`ScoreBuilder` は `soundStartSec - 0.15 s` より前の音符を落とす（モデルが窓境界で少し早く置くことがあるため 0.15 s の猶予）。
落とした結果 3 音未満になる場合は**何も落とさない**（測定ミスで録音を空にしない）。

### 2. 演奏前の孤立した物音を落とす（`ScoreBuilder.trimLeadingNoise`）

音符をアタック（90 ms 以内は同じ打鍵）にまとめ、さらに**4 拍を超える間隔**で「演奏の連なり」に区切る。
先頭の連なりが

- 音符がごく少ない（全体の 5 % 以下、かつ 4 アタック以下）で、
- 次の連なりと 4 拍以上離れている

なら、それは演奏ではなく物音なので読み飛ばす。テンポは「4 拍」を知るために一度推定し、削ったあとに推定し直す。
跳ねるような物音が 1 つ混ざっただけでテンポ・拍子が壊れていたのもこれで直る。

**残すもの**: 曲が本当に 1 つの和音から始まり、そのまま続く場合は落とさない（間が 4 拍以内なので同じ連なりになる）。
6 音以下の短い録音は判定しない。

### 3. ライブ楽譜も最初の音から描く（`domain/live/LiveStaffLayout`）

`x = origin + (onset - 最初の音符の onset) × px/秒` に変更。待ち時間は五線に出ず、音符の間隔（テンポ感）は変わらない。

### 4. 弱起小節の保証

`buildMeasures` の弱起（先頭小節の長さ = 最初の音から最初の強拍までの拍数、`implicit="yes"`）はそのまま。
beat 0 が「無音を除いた最初の音」になるので、**第 1 小節が休符で始まることは構造的にない**。
これをテストで固定した（弱起 0 / 1 拍 / 半拍 = 裏拍 / 3 拍の 4 パターン）。

## 検証

- **ユニットテスト**: 266 件すべて合格（3 件は環境変数がないとスキップされるベンチマーク）。新規 18 件。
  - `ScoreStartTest`（11 件）: 無音の先頭、タップ音、無音中の幻の音符、音が最初から鳴る録音、誤測定で録音を空にしないこと、開幕の和音を残すこと、拍頭/1 拍/半拍/3 拍の弱起と MusicXML の `implicit="yes"`・先頭が音符であること、弱起のあとに空の小節が入らないこと。
  - `SilenceHeadTest`（6 件）: 無音の長さ、小さい演奏、単発クリック、最初から鳴る録音、定常ノイズ、空/無音。
  - `LiveStaffLayoutTest`（+1 件）: 待ち時間が五線の先頭に出ないこと。
- **PianoVAM 10 曲**（`work/pianovam/replay`）: 変更前後でテンポ・拍子・調・小節数・`scoreStartSec`・音符数が**すべて一致**（劣化なし）。
  10 曲とも「最初の音の 0.15 s 以内に鳴り始めている」ので、無音トリムは何も落とさない。
- **実録音 fixture**（`RealTakeAnalysisTest` 5 件）: エリーゼのために・ジムノペディ・本人の録音、いずれも合格のまま。

## 実機での確認ポイント（0.4.3）

1. 録音ボタンを押して数秒待ってから弾く → 楽譜の第 1 小節が**そのまま最初の音**から始まる（待ち時間の休符・空の小節がない）。録音中のライブ五線も、最初の音が左端に出る。
2. 8 分の裏から弾き始める → 第 1 小節が半拍の弱起（`implicit="yes"`）で、その次の小節から 4/4 の本則。
3. 4 拍目から弾き始める → 1 拍の弱起。
4. 拍頭から弾き始める → 弱起は入らず、第 1 小節はフルの小節。
5. 解析後のヘッダ（テンポ・拍子・調・音符数）が、以前の解析と大きく変わっていないこと（変わった場合は無音側の誤検出が取れた分）。

## 既知の制限

- 拍子・弱起の長さは曲全体のアクセント分布から決める。冒頭だけ極端にアクセントが弱い曲では、弱起の長さが 1 拍ずれることがある（先頭が休符になることは、上記のとおりない）。
- 先頭が**左手だけ**の場合は、右手の五線に休符が入る（記譜上正しい）。「空白にしない」対象は音が鳴っている五線。
- 演奏前の物音と、曲の冒頭の孤立した和音の区別は**時間の間隔**で行う。冒頭の和音から 4 拍以上あけて演奏が始まる曲では、その和音が物音として落ちる可能性がある（音の大きさでは判定していない）。
- 音が小さい演奏（マイクから遠い）では `SilenceHead` のしきい値が下限 -55 dBFS になるため、部屋の暗騒音がそれ以上だと無音と判定されず、トリムは働かない（安全側）。
