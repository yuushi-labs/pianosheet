# ノイズ除去のマイルド化と高音ノイズ対策（0.4.4）

対象: `0.4.4-phase2`（versionCode 11）

要望（ゆうし）:

> 今試してみた感じ、ノイズ除去が弱の方が1番音を正確に捉えてる感じあったんだけど、そのかわり高い音のノイズが乗ってるから、１回スピーカーでピアノ流してやってみるわ
> やっぱり高音ノイズとノイズ除去は弱の方がいいかんじだった
> もうちょい全体的にノイズ除去軽減させてもいいかも(今の弱を標準にするぐらい)
> スピーカーにしても高音ノイズ混じるね 前よりは軽減されたけど

材料は実機で録った生 WAV 4本（すべて 22.05 kHz / 16 bit / モノラル）。

|---|---|---|---|---|

| B | `rec-20261118-141453-…wav` | 31.0 s | −27.5 dBFS | 静かな録音。演奏は 5.5 s から 29.3 s |
| C | `rec-20261118-141746-…wav` | 40.3 s | −24.1 dBFS | 40 s 通し。環境ノイズが最も多い |

解析は Kotlin と同じ順序の Python 再現（`Denoiser` → `StartupGuard` →
PTI-ONNX（`piano-notes-v1.onnx`）→ `PtiPostProcessor`（decay trim 30 %）→
`SilenceHead` → `HarmonicRealnessFilter.PTI`）で行い、4本 × OFF / 弱 / 標準 の
12通りを比較した。

## 1. 4本で分かったこと

### 1.1 どの帯域に何が乗っているか

20 ms フレームの小さい方から 15 % を「無音」、大きい方から 15 % を「演奏」として
帯域ごとのレベルを測った（A は物音の区間を除く）。

| 録音 | 80–315 Hz | 315–1250 Hz | 1250–2500 Hz | 2500–5000 Hz | 5000–8000 Hz |
|---|---|---|---|---|---|
| A 無音 / 演奏 | −45 / −7 | −47 / +1 | −46 / +10 | −48 / +8.5 | −40 / −7 |
| B 無音 / 演奏 | −50 / −25 | −51 / −10 | −51 / −4 | −52 / −14 | −56 / −36 |
| C 無音 / 演奏 | −31 / −18 | −25 / −3 | −20 / +3 | −28 / −13 | −47 / −31 |
| D 無音 / 演奏 | −22 / −20 | −12 / +5 | −12 / 0 | −25 / −5 | −38 / −35 |

- どの録音も**低音が細く、1–2 kHz が出ている**（スマホのマイクとスピーカーの
  特性）。そのため中音域の鍵盤は基音より**2倍音・3倍音の方が大きい**ことが普通に
  起きる（例: 演奏中の D#5 = 622 Hz は −74 dB、その2倍音 1.25 kHz は −68 dB）。
- 残る高音ノイズは **1.5–3 kHz** に集中している。C と D では 1.25 kHz 付近が
  ほぼ全編で鳴り続けており、C では**その帯域のレベルが演奏中の平均より大きい**。
- 定常音検出（`ToneNoiseDetector`）は **C で 1.25 kHz** を検出した（40 s の
  80 % のフレームで、周囲より 15 dB 以上突出）。ところがこの線は**単一の正弦波
  ではなく 1.2–1.28 kHz に広がるクラスタ**で、周波数も 1244 Hz 付近で固定。
  基音 311 Hz（D#4）は −22 dB しかなく、ピアノの倍音列（1/k^1.5）では説明できない。
  **部屋かスピーカーの 1.25 kHz の共振**が、演奏のエネルギーで鳴っているもの。

### 1.2 高音ノイズ（誤検出ノート）の正体

4本を現行の経路に通し、残った高音（MIDI 84 以上 = C6 以上）を1音ずつ
スペクトルで確認した。出ていたのは次の3種類。

| 種類 | 出方 | 例（A / C） | 判定の手がかり |
|---|---|---|---|
| ① 4倍音・8倍音のゴースト（+24 / +36 半音） | 低音の4倍音・8倍音の位置に細い線。デノイズ OFF だと 2 オクターブ上（MIDI 94–103）に層になって出る | A OFF: 99 (D#7) が 24 回、101 (F7) が 6 回。**弱にすると 7 回、標準で 1 回**まで減る | 線が細く、2倍音・3倍音が無い（既存の純音テストで捕捉） |
| ② オクターブゴースト（+12 半音） | 基音が細く2倍音が大きい録音なので、モデルが**下の鍵盤の2倍音を上の鍵盤として報告**する。しかもその「2倍音」は下の音の4倍音と重なるため、**純音テストが通ってしまう** | A 弱: G6 (91) が f0/2 の 1.4–2.1 倍のエネルギーで 3 回、G#6 (92) が 2.1 倍で 1 回 | 線の下（f0/2）に、それより強いエネルギーがある |
| ③ 定常線（共振・持続音） | 1.25 kHz の共振を D#6 として、その2倍音 2.49 kHz を D#7 として、**打鍵の無い区間にも**並べる。減衰しない | C 弱: D#7 が 19 回、D#6 が 26 回。うち 44 回は下に持ち主のノートが無い | 線が減衰しない（0.3 s で −1 dB 未満）／下の帯域にエネルギーがある |

②③ が 0.4.3 で残っていた理由:

- 純音テストは「自分の2倍音・3倍音が無いか」を見るが、**オクターブゴーストの
  "2倍音" は下の鍵盤の4倍音そのもの**なので、純音に見えない（h2 = 0.4〜0.7）。
- 持ち主テストは「12/24/36 半音下のノートが同時に検出されているか」を見るが、
  ②では下の鍵盤が検出されないことがあり、③では共振なので最初から下の鍵盤が無い。
  どちらも「純音だが持ち主なし」として**残していた**。

### 1.3 0.4.3 の先頭処理は効いている

`SilenceHead` の鳴り始めは A 0.46 s / B 2.26 s / C 1.24 s / D 1.06 s で、実際の
演奏開始（A 4.6 s、B 5.5 s）より前を指す（物音や残響を拾うため）。ただし楽譜の
原点は `ScoreBuilder` の**最初の音符**なので、4本とも先頭に空の小節は出ない。
`0.4.3` の「演奏前の物音を落とす」も、A の開始 0–1.5 s の物音が音符になって
いないことで確認できた。

## 2. 直したこと

### 2.1 ノイズ除去を1段マイルドに（`DenoiseConfig` / `DenoiseStrength`）

0.4.3 の「弱」をそのまま新しい「標準」にし、全体を1段ずらした。

| 強さ | 0.4.3（oversub / floor / smoothing） | 0.4.4 |
|---|---|---|
| 弱 | 0.7 / −8 dB / 0.60 | **0.45 / −5 dB / 0.65** |
| 標準 | 1.4 / −14 dB / 0.50 | **0.7 / −8 dB / 0.60**（= 0.4.3 の弱） |
| 強 | 3.0 / −24 dB / 0.45 | **1.4 / −14 dB / 0.50**（= 0.4.3 の標準） |

既定は「標準」のままなので、**アプリを更新すると今まで「弱」で聞いていた音が
そのまま既定**になる。

### 2.2 高域だけは削る（`DenoiseConfig.highBand*`）

1.2 kHz から 1.8 kHz にかけて、減算係数をプリセットの **2.0 倍**まで、ゲインの
下限を **4 dB** 深くする。ピアノの胴（〜1 kHz）はマイルドなまま、**高音ノイズが
出る 1.5–3 kHz のヒスだけ**を今までどおり落とす。

- A: C6 以上のノートが **12 → 7**（全体のノート数は 127 → 124）。
- PianoVAM 6曲（実ピアノ、2,220音符）: pv29 **0.987 → 0.989**、pv74 **0.996 → 0.995**。
  実ピアノの高音・和音は落ちていない。

### 2.3 倍音実在チェックを強化（`HarmonicRealnessFilter.PTI`）

1. **対象を C5（MIDI 72）まで広げた。** 0.4.3 は C6 以上だけを見ていたが、
   オクターブゴーストは C5–B5 にも出るため。
2. **スペクトル側の持ち主テストを追加**（`spectralOwnerRatio = 0.25`）。純音の
   ノートは、**f0/2 または f0/4 の帯域が f0 の 25 % 以上**あれば、下の音の
   2倍音・4倍音そのもの＝ゴーストとして落とす。下の鍵盤が検出されていなくても
   効くので、②③ の取りこぼしを拾う。
3. 持ち主の音程に **+19 半音（3倍音）** を追加。

効果（4本、既定の「標準」で解析した最終ノート数）:

| 録音 | 0.4.3 標準 | 0.4.3 弱 | **0.4.4 標準** |
|---|---|---|---|
| A | 120（C6+ 8） | 127（C6+ 12） | **124（C6+ 7）** |
| B | 143（7） | 155（7） | **156（8）** |
| C | 250（46） | 284（85） | **279（41）** |
| D | 153（4） | 162（5） | **166（4）** |

「弱」で取りこぼしていた音はそのまま残り（ノート数は弱と同水準）、C6 以上の
ゴーストだけが 0.4.3 の標準より少なくなった。特に C（40 s・共振あり）で
**C6+ が 85 → 41**。

### 2.4 定常音のノッチを深く（`toneNotchGainDb`）

−18 dB / ±2 bin → **−26 dB / ±3 bin**。C の 1.25 kHz 共振は −18 dB では
線が残り、モデルが D#6 を出し続けた。−26 dB にすると D#6 のノートが 38 → 25 に
減り、C6+ が 41 まで下がった。実ピアノ（PianoVAM pv29 は 1.67 / 2.52 / 3.39 kHz に
定常音が検出される曲）でも F1 は変わらない（−18 dB と同値）。

### 2.5 ライブ経路（`denoiseConfigForLive`）

ライブ表示は強さの設定に関係なく「弱」で適用していた。新しい「弱」は 0.4.3 の
「弱」よりマイルドなので、そのままにすると**録音中の譜面だけ高音ゴーストが増える**。
そこでライブ経路は新しい「標準」（= 0.4.3 の「弱」）に合わせ、挙動を据え置いた
（設定画面の文言も「標準で適用」に更新）。

## 4. 残っている制限

- 1.25 kHz のような**共振そのものは消せない**。ノッチで十分下げると 41 まで
  減るが、共振が鳴っている間はどうしても一部が D#6 として残る。録音環境
  （スピーカーの位置・音量）を変えるほうが効く。
- オクターブを実際に重ねて弾く（オクターブ奏法）箇所で、上の音の倍音が
  下の音に埋もれていると、②のルールが上の音を落とす可能性は残る。PianoVAM の
  6曲では該当 0 件。
